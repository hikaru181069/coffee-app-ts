# サーバーのファイルの分け方

```
server/src/
├ index.ts           サーバーを起動し、機能ごとの routes をつなぐ
├ auth/              ログインまわり
│ ├ routes.ts        お願いを受けて、返す
│ ├ middleware.ts    API の前に通す関所（ログインしているかの確認）
│ ├ service.ts       中身の処理（登録・ログインの手順など）
│ ├ users.ts         users 表とのやりとりだけ
│ └ sessions.ts      sessions 表とのやりとりだけ
├ lib/               どこでも使う小さい道具（パスワードの変換など）
└ db/                表の設計図（schema.ts）、つなぎ方、選択肢の中身
```

## ルール

- 機能ごとにフォルダを分ける（auth/・records/ など）
- フォルダの中は、役割ごとにファイルを分ける（routes → service → 表とのやりとり → db）
- 上から下へだけ呼ぶ。routes からデータベースを直接さわらない
- 手順があるときだけ service を作る。ないときは、routes から repository を直接呼んでよい（例: options/ は一覧を取り出して返すだけなので、service がない）

## なぜこうしたか

- 機能ごとにフォルダを分けた。最初は役割ごとのフォルダ（routes/・services/ など）にしたが、1つの機能のファイルがいくつものフォルダに散らばり、同じ名前のファイル（auth.ts）がいくつもできて、どこに何があるか分かりにくかったため
- フォルダの中では役割ごとにファイルを分けた。混ざった処理をあとから役割ごとに分けるのは大変なので、アプリを発展させていくことを考えて、最初から分けておく
- 中身の処理（service）が、お願いの受け答えやデータベースと分かれているので、関数だけを取り出してテストしやすい
- 候補: 種類で分ける（routes と lib だけ。かんたんだが、機能が増えると処理が混ざりやすい）、役割ごとのフォルダ（最初にこうしたが、上の理由でやめた）
