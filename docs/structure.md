# サーバーのファイルの分け方

```
server/src/
├ index.ts         サーバーを起動し、routes をつなぐ
├ routes/          お願いを受けて、返す
├ middleware/      API の前に通す関所（ログインしているかの確認など）
├ services/        中身の処理（登録・ログインの手順、グラフの計算など）
├ repositories/    データベースとのやりとりだけ
├ lib/             どこでも使う小さい道具（パスワードの変換など）
└ db/              表の設計図（schema.ts）、つなぎ方、選択肢の中身
```

## ルール

- 上から下へだけ呼ぶ（routes → services → repositories → db）
- routes からデータベースを直接さわらない

## なぜこうしたか

- 役割の段で分けた。混ざった処理をあとから役割ごとに分けるのは大変なので、アプリを発展させていくことを考えて、最初から分けておく
- 中身の処理（services）が、お願いの受け答えやデータベースと分かれているので、関数だけを取り出してテストしやすい
- 候補: 種類で分ける（routes と lib だけ。かんたんだが、機能が増えると処理が混ざりやすい）、機能で分ける（auth/・records/ のように機能ごとのフォルダ。機能は見つけやすいが、フォルダの中で役割が混ざりやすい）
