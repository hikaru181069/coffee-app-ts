# 道具選び

- 言語: TypeScript（前は JavaScript 中心・一部 TypeScript）
- データベース: PostgreSQL（前は MongoDB）
- サーバーの土台: Hono（前は Express）
- データベースを使う道具: Drizzle（前は Mongoose）
- 画面の土台: React ＋ Vite（前と同じ）
- テスト: Vitest（前と同じ）
- パスワードの変換: Argon2（前は bcrypt）
- 公開する場所: VPS 1台（Caddy・Hono・PostgreSQL）※仮（前は Vercel・Render・MongoDB Atlas）

## なぜこうしたか

### データベース: PostgreSQL

- 記録は産地・精製方法などの選択肢を参照し、品種やフレーバーは1つの記録に複数付く。こういう「表どうしのつながり」が得意
- 「評価は 1〜10」「名前は必須」のような決まりを、データベースに守らせられる
- 前のアプリは MongoDB で、つながりや決まりをコード側で守っていた。そこを変えた
- 候補: MySQL（ほぼ同じことができるが、無料の置き場所と情報の多さで PostgreSQL にした）、Neo4j などのグラフ専用データベース（ふつうの記録の保存に向かず、学ぶことも増えるのでやめた）

### サーバーの土台: Hono

- 最初から TypeScript 前提で作られていて、型の助けが強い。TypeScript を覚えるのに向いている
- 軽いので、ファイルの分け方などの構成を自分で考えることになる
- 書き方は Express とほぼ同じ。前のアプリは Express だったので、今回は TypeScript と親和性の高い Hono にした。
- 候補: Express（情報は一番多いが、型の助けが弱い）、NestJS（覚えることが多く、スケジュールに対して重い）

### データベースを使う道具: Drizzle

- 書き方が SQL に近いので、使いながら SQL を覚えられる
- 知識グラフの計算のような少し複雑な取り出し方を書きやすい
- 表の形も TypeScript で書けて、専用の書き方を覚えなくてよい
- 候補: Prisma（情報が多くかんたんだが、SQL がほぼ見えない）

### 画面の土台: React ＋ Vite

- サーバーは Hono に任せるので、画面とサーバーの役割をはっきり分けられる。データの流れも説明しやすい
- 画面を作る期間は2週間なので、覚えることが少ないほうが安全
- 候補: Next.js（サーバーの仕事が Hono と重なり、覚えることも多い）

### テスト: Vitest

- TypeScript をそのまま使える
- 画面の Vite と同じ仲間なので、画面とサーバーで同じテストの道具をそろえられる
- 候補: Jest（書き方はほぼ同じだが、TypeScript を動かす設定が別に必要）

### パスワードの変換: Argon2

- パスワードを元に戻せない形に変える方法として、今いちばん勧められている
- 「変える」「照らし合わせる」の2つの関数で使えて、かんたん
- 候補: bcrypt（前のアプリで使っていた。昔からよく使われている）、scrypt（Node.js に最初から入っているが、自分で書く部分が多い）

### 公開する場所: VPS（仮）

- 止まらない（無料のサービスのように、開くまで待たされることがない）
- サーバーの中身を自分で組むので、Linux やサーバーの知識が身につく
- フェーズ④の Docker で、3つをまとめて動かせる
- 気をつけること: 月 500〜1,000円ほどかかる。ドメイン（URL）代も年に 1,000〜2,000円ほどかかる。勝手に入られないための設定・更新・バックアップを自分でやる
- 候補: Vercel・Render・Neon（無料だが、サーバーが止まって開くのが遅くなることがある）、AWS（多くの会社で使われているが、むずかしく、思わぬ請求の心配がある。余裕ができたら移す）
