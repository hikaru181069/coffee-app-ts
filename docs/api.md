# API

## ログイン

- `POST /api/auth/register` ユーザー登録
- `POST /api/auth/login` ログイン
- `POST /api/auth/logout` ログアウト
- `GET /api/auth/me` どのユーザーがログインしているか確認する
- `PATCH /api/auth/me` 名前を変える
- `PATCH /api/auth/password` パスワードを変える
- `DELETE /api/auth/me` 退会
- `POST /api/auth/demo` デモアカウントを作って、ログインする

### デモアカウント

- 押すたびに、その人専用のデモアカウントを作り、サンプル記録を写して入れる。
- メールアドレスとパスワードは自動で作り、本人には見せない。
- 作ってから24時間たったデモアカウントは、だれかが「デモで使う」を押したついでに消す。
- デモアカウントのログインは24時間で切れる。
- パスワードを知らないので、デモアカウントではパスワードの変更と退会はできない(24時間で自動で消える)。

### ログインの方法

- セッションを使う。ログインすると、サーバーが受付番号を作ってデータベースに保存し、ブラウザのクッキーに入れる。
- クッキーは、画面のプログラムから読めない設定にする。
- ログアウトすると、その受付番号を消す。
- パスワードを変えたとき、退会したときは、その人の受付番号を全部消す。

## 記録

- `GET /api/records` 自分の記録の一覧(飲んだ日が新しい順。同じ日なら作った日時が新しい順)
  - `?limit=5` 新しい順に5件だけもらう(ホームの最近の記録に使う)
  - タグでしぼりこむ(そのタグに該当する記録だけを返す)
    - `?origin=〇` 産地
    - `?variety=〇` 品種
    - `?process=〇` 精製方法
    - `?roast=〇` 焙煎度
    - `?flavor=〇` フレーバー
- `POST /api/records` 記録を作る
- `GET /api/records/:id` 記録を1件見る(:idは記録の番号)
- `PATCH /api/records/:id` 記録を直す
- `DELETE /api/records/:id` 記録を消す

## 選択肢の一覧

- `GET /api/options` 産地、品種、焙煎度、フレーバー、精製方法の一覧を返す。

## 知識グラフ

- `GET /api/graph` 自分の記録から作ったグラフ(点と線)のデータを返す。

## サーバーの確認

- `GET /api/health` サーバーが動いているか確かめる。

## エラーの返し方

- エラーのときは、全部この形で返す。`code` はプログラムが見る用、`message` は人が読む用。

```json
{ "error": { "code": "record_not_found", "message": "記録が見つかりません" } }
```

- 入力が決まりに合わないときだけ、どの項目がまちがっているかを `fields` に入れる。

```json
{
  "error": {
    "code": "validation_error",
    "message": "…",
    "fields": { "rating": "…" }
  }
}
```

- `validation_error` 400 入力が決まりに合わない。
- `invalid_json` 400 送られてきた中身が壊れている。
- `wrong_password` 400 パスワードの変更、退会で、パスワードが違う。
- `unauthorized` 401 ログインしていない。
- `invalid_credentials` 401 ログインで、メールかパスワードが違う。
- `demo_user` 403 デモアカウントで、パスワードの変更、退会をしようとした。
- `record_not_found` 404 記録がない(他の人の記録も含む)。
- `not_found` 404 ないURL。
- `email_taken` 409 そのメールアドレスはもう使われている。
- `internal_error` 500 サーバーで思わぬ失敗が起きた。

## なぜこうしたか

- ログインはセッションを選んだ。他の候補はJWTだが、JWTはログアウトしても一定期間使えてしまうことがあるため。
- デモアカウントは、押した人ごとに別のアカウントを作るようにした。全員で1つを使うと、だれかが消したり足したりした記録が次の人にも見えてしまうため。見るだけにすると、アプリの記録を試せないため。
- 作ってから24時間たったデモアカウントは、新しいデモアカウントが作られた時に消える。時間で消す仕組みはMVPのレベルを超えてしまうと判断したから。
- 最近の記録とタグでのしぼりこみは、新しい API を作らず、記録の一覧 API に条件を付ける形にした。URLを増やすと、作業が増える。あとで直すときもURLの数だけ直す必要があり、直し忘れると不具合が残るため。
- 記録の並び順は、記録した順ではなくて、コーヒーを飲んだ順にした。記録はコーヒーを飲んだからするものだから、その方が自然だと感じたから。同じ日の記録は作った日時の順にして、順番が毎回変わらないようにした。
- タグの絞りこみは、種類ごとに名前を分けた(`?origin=3` など)。選択肢の番号は種類ごとに付くので、`?tag=3` の1つにまとめると、産地の3番かフレーバーの3番か見分けられないため。また、複数を組み合わせることも可能。
